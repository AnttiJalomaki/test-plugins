# Autogenerate and Rendering

## Preserve expression and constraint values

Since 1.15.0, autogenerate preserves labels on index expressions. PostgreSQL
operator classes keyed by a label name can therefore render against that name.

Autogenerate also renders a boolean `UniqueConstraint.deferrable` with its
Python representation:

```python
sa.UniqueConstraint("name", deferrable=True)
```

It does not emit quoted boolean text such as `deferrable="True"`.

## Consume detected-diff context

`AutogenerateDiffsDetected` includes the revision context as of 1.15.0.
Command wrappers can inspect this context when emitting detected diffs in
another format.

## Render rewriter-provided column names

As of 1.15.2, rendering considers `AlterColumnOp.modified_name`. A custom
autogenerate `Rewriter` that assigns this attribute produces an operation with
the renamed column.

Alembic still does not detect column renames automatically; the rewriter must
identify and annotate the rename.

## Respect the configured operations prefix

Since 1.16.0, a custom writer that embeds `ExecuteSQLOp` gets
`Operations.execute()` rendered with the namespace in
`alembic_module_prefix`. Rendering no longer always hardcodes `op.`.

## Protect final reflected names

Since 1.16.0, autogenerate applies `Operations.f()` to every reflected
constraint and index name:

```python
op.drop_constraint(op.f("uq_account_name"), "account", type_="unique")
```

The marker tells an active naming convention that the database name is already
final. This prevents a second transformation and avoids failures for
conventions using the `%(constraint_name)s` token.

## Compare PostgreSQL defaults without cast noise

As of 1.18.0, PostgreSQL autogenerate ignores server-added `::regclass` casts
while comparing sequence defaults on non-primary-key columns. An unchanged
sequence default therefore does not recur as a generated diff.

## Render PostgreSQL included columns as names

As of 1.18.0, autogenerate renders `Column` objects inside sequence-valued
dialect arguments such as `postgresql_include` as string column names. The
result is valid Python rather than a representation of the `Column` object.

## Handle filtered foreign-key targets

As of 1.18.0, autogenerate does not raise `NoReferencedTableError` merely
because a foreign key's target table was excluded by `include_name` or its
schema was omitted from reflection.

An `include_object` callback that inspects such a constraint may see a
placeholder target table. Rely only on the placeholder's table name, schema,
and referenced columns; it is not a fully reflected table.

## Compare MySQL ENUM values

As of 1.18.0, autogenerate compares individual MySQL `ENUM` values. A value
present on only one side produces a diff. A change that only reorders the same
values does not produce a diff.
