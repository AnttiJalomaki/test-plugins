# CLI, testing, and formatting

## Check and rewrite legacy Rego

Use an OPA v1 binary in dual-version mode to expose syntax and compilation
incompatibilities, retain the former strict checks, and rewrite before linting:

```sh
opa check --v0-v1
opa check --v0-v1 --strict
opa fmt --write --v0-v1
regal lint
```

This is the required migration path from the `1.0-migration` batch. For an
individual legacy module, OPA 1.6.0 adds:

```sh
opa parse --v0-compatible policy.rego
```

`opa check --bundle` detects base JSON or YAML documents that overlap virtual
documents generated by Rego rules since 1.6.0:

```sh
opa check --bundle ./bundle
```

Resolve every ambiguous path before accepting the bundle.

## Formatting behavior

- Since 1.0.0, formatting in v1 mode preserves `rego.v1` and
  `future.keywords` imports so modules retain compatibility intent for older
  consumers.
- OPA 1.4.0 fixes formatter changes to string contents and a panic on
  unexpected comments. Reformat with a fixed binary before trusting earlier
  diffs.
- Since 1.13.0, `opa fmt` does not overwrite unchanged files, preserving their
  modification times.
- OPA 1.18.0 accidentally expanded single-item arrays, objects, and sets onto
  multiple lines. Use 1.18.2 or later; it restores source-newline-driven
  one-line versus multiline layout. The 1.18 formatter also preserves `with`
  clauses after comments in object values and lone `with` placement on closing
  bracket lines.

## Parameterized tests

OPA 1.2.0 lets a test rule generate hierarchical named cases from its head.
Each case is reported separately so a failure does not hide other inputs.

```rego
package example_test

test_concat[note] if {
    some note, tc in {
        "empty": {"a": [], "b": [], "want": []},
        "filled": {"a": [1], "b": [2], "want": [1, 2]},
    }
    array.concat(tc.a, tc.b) == tc.want
}
```

OPA 1.3.0 corrected the report counter to include parameterized cases. In
non-verbose mode its summary contains only failed sub-test cases.

## Parallelism, ordering, and streaming

Since 1.6.0, `opa test` uses one execution thread per available CPU core by
default. Force serialized execution when tests share state or ordering:

```sh
opa test . --parallel=1
```

OPA 1.13.0 can sort JSON-format results by duration. Since 1.17.0, results
stream one case at a time and failures under `--coverage` include full errors.
Output consumers must tolerate incremental results rather than assuming one
final result block.

OPA 1.18.0 coverage reports include source ranges and track inline rule heads
and conjunction expressions. Rebaseline expected locations and totals after an
upgrade.

## `eval`, `exec`, and debugging

- The debugger accepts YAML input since 1.0.0.
- Since 1.2.0, `opa exec` results include a decision ID for correlation with
  decision logs and traces.
- Since 1.9.0, `opa eval` sends evaluation errors to stderr. Automation must
  capture stderr separately instead of parsing stdout for errors.

## Optimized bundle entrypoints

Since 1.3.0, optimized bundle builds reject single-term entrypoint paths. Name
at least the package and rule:

```sh
opa build -O=1 -e=authz/allow .
```
