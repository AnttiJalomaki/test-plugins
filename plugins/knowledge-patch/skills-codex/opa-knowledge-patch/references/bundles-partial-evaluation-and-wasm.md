# Bundles, partial evaluation, and Wasm

## Upgrade mixed-version bundle systems

For the 1.0 migration, upgrade producers before consumers. Bundles built by OPA
v0.64.0 or later contain `rego_version`; that embedded value takes precedence
over `--v1-compatible` on a v1 consumer.

While any v0 consumer remains, policy must stay v0-compatible and v1 producers
must use `--v0-compatible` unless their modules import `rego.v1`. Conversely, a
v1 consumer loading a bundle from an older producer must use
`--v0-compatible`, because the bundle cannot declare its Rego version.

Policies uploaded through the REST policy API honor the runtime Rego version
since 1.0.0. Since 1.5.0, the bundle API assigns a default Rego version when a
caller omits one; embedded producers must not assume omitted metadata stays
unset.

OPA 1.18.0 fixes per-module Rego-version selection and resolves overlapping
`file_rego_versions` patterns deterministically. Recheck mixed-version bundles
whose manifests contain overlapping patterns.

## Bundle validation and loading

Optimized bundle entrypoints must include at least a package and rule since
1.3.0, for example:

```sh
opa build -O=1 -e=authz/allow .
```

Since 1.6.0, `opa check --bundle` reports collisions between JSON or YAML base
documents and virtual documents generated by rules. Resolve the ambiguous paths
before deployment.

Bundle plugin trigger methods support direct error handling since 1.0.0, so
integrations can handle trigger failure at the call site. Bundle polling
intervals are validated since 1.12.0, preventing an invalid value from causing
nanosecond-level polling.

Prometheus configuration can define histogram buckets for
`bundle_loading_duration_ns` since 1.0.0. Choose buckets that reveal the load
latencies relevant to the deployment.

## Capability files

Capabilities produced under `--v0-compatible` include the `rego_v1` feature
since 1.4.0; capability consumers must not infer that v0 compatibility excludes
it. OPA 1.4.1 omitted `capabilities/v1.4.1.json`; use 1.4.2 when tooling consumes
versioned capability files.

## Partial evaluation

OPA 1.1.0 adds an opt-in for evaluating nondeterministic built-ins during
partial evaluation in Topdown, the Rego API, and server evaluation. The same
release makes `opa eval --v0-compatible` apply that mode to generated support
modules.

Correctness changes require revalidation:

- Since 1.4.0, partial evaluation handles default functions correctly.
- Since 1.4.0, Topdown `PartialRun()` initializes wall-clock time, correcting
  evaluations that use time-dependent built-ins.
- Since 1.18.0, improved negation works correctly inside `every`, and variables
  are namespaced in comprehensions nested inside `every`.

Residual policy and results can change for each affected query.

## Wasm bundle construction and behavior

OPA 1.0.0 adds a build option to preserve `print` statements when targeting
Wasm. Enable it when the deployed bundle needs print diagnostics.

OPA 1.3.0 corrected an over-eager planner optimization for reference-head
rules. Wasm and non-Wasm evaluation now agree, so policies affected by the bug
can return different Wasm results after upgrade.

OPA 1.18.0 moves the `wasm` target and WASM SDK from `wasmtime-go` to the
pure-Go wazero runtime. Wasm-enabled builds no longer need cgo or a C toolchain.
