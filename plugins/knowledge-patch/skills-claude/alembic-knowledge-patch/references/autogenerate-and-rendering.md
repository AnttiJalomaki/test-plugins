# Autogenerate and rendering

## Index and constraint rendering

### Labeled index expressions

Autogenerate preserves labels on index expressions. This permits PostgreSQL
operator classes keyed by a label name to render correctly. Do not strip a
label merely because the underlying expression remains otherwise unchanged.
(since 1.15.0)

### Boolean `UniqueConstraint.deferrable`

Autogenerate renders the boolean `deferrable` value using its Python
representation. Generated operations contain `deferrable=True` or
`deferrable=False`, not quoted boolean text. Custom rendering checks should
expect a boolean literal. (since 1.15.0)

### Final reflected names

Autogenerate applies `Operations.f()` to every reflected constraint and index
name. The wrapper marks a name as already finalized so a naming convention does
not transform it again. This prevents failures for naming conventions that use
the `%(constraint_name)s` token. (since 1.16.0)

```python
op.drop_constraint(op.f("uq_account_name"), "account", type_="unique")
```

### PostgreSQL included columns

For sequence-valued dialect arguments such as `postgresql_include`,
autogenerate renders `Column` objects as string column names rather than as
invalid Python object representations. (since 1.18.0)

## Custom autogenerate pipelines

### Revision context on detected diffs

`AutogenerateDiffsDetected` includes the revision context. Command wrappers can
read that context when translating detected diffs into another output format.
(since 1.15.0)

### Rewriter-driven column renames

Alembic still does not detect column renames automatically. A custom
autogenerate `Rewriter` can identify a rename and set
`AlterColumnOp.modified_name`. Rendering honors that attribute as of 1.15.2,
so the resulting operation directive uses the renamed column. (1.15.0)

### Configured operation prefix for SQL execution

When a custom writer embeds `ExecuteSQLOp`, autogenerate renders
`Operations.execute()` with the namespace selected by `alembic_module_prefix`.
It no longer always hardcodes `op.`. Writers and golden-file tests should allow
the configured prefix. (since 1.16.0)

### Conditional-operation flags

Custom `Rewriter` recipes can attach `if_not_exists=True` to an add-column
operation or `if_exists=True` to drop-column and drop-constraint operations.
The rendered migrations then preserve the conditional DDL flags. (since
1.16.0)

## Comparison behavior

### PostgreSQL sequence defaults

PostgreSQL can add a `::regclass` cast to sequence defaults. Autogenerate
ignores this server-added cast when comparing sequence defaults on
non-primary-key columns, preventing an unchanged default from recurring as a
diff. (since 1.18.0)

### MySQL `ENUM` values

Autogenerate compares individual MySQL `ENUM` values. A value present on only
one side produces a diff. A change only in value order does not produce a diff.
(since 1.18.0)

## Filtered foreign-key targets

Autogenerate does not raise `NoReferencedTableError` when a foreign key points
to a table excluded by `include_name` or omitted from the reflected schemas.
(since 1.18.0)

An `include_object` callback that inspects such a constraint can see a
placeholder target table rather than a fully reflected table. The placeholder
contains the target table name, schema, and referenced columns. Callback code
should use only the available identity information unless it first verifies
that full reflection occurred.
