# C++ Language and Modules

Check exact compiler support for each proposal. Draft-mode names and feature
macros can lag or lead implementation details.

## Constant evaluation and defect-resolution changes

### Pointer expressions (clang-20.1)

Comparing different evaluations of the same string literal is non-constant,
while comparisons of literals that cannot overlap can evaluate to `false`.
Forming a field address through a null pointer, such as
`&((S *)nullptr)->member`, is rejected in a constant expression.

### Initialization, deduction, and core behavior (clang-20.1)

For a `T` prvalue `e`, Clang prefers a viable initializer-list constructor for
`T{e}` before guaranteed copy elision. Suitably narrow bit-fields are
non-narrowing, `nullptr` promotes to `void *` through C-style varargs, and
`void{}` is accepted. Trailing requires-clauses are accepted on explicit
deduction guides, and constructor constraints propagate into CTAD.

### Template lookup timing (gcc-15.1)

Invalid lookup into the current template instantiation is diagnosed while the
template is parsed rather than only during instantiation.

### Non-template overloads can avoid instantiation (clang-21.1)

Under implemented parts of P3606, an identity-conversion match from a
non-template candidate prevents template candidates from being instantiated.
Diagnostics formerly produced only by those unused instantiations can
therefore disappear.

### Constraint and constant-evaluation checks (clang-22.1)

Clang normalizes constraints before satisfaction checks, rejects sibling-member
pointer access during constant evaluation, type-checks constant template
parameters in template definitions, and disallows immediate escalation in
destructors. Constexpr structured bindings work for arrays and aggregates, but
not references or tuple-like decomposition.

## C++20 and C++23 language support

### Clang language behavior (clang-20.1)

C++23 mode implements range-for temporary lifetime extension (P2718R0), permits
unknown pointers and references in constant expressions (P2280R4), removes the
literal-type restriction in constexpr functions, and defines
`__cpp_explicit_this_parameter`. C++20 modules perform module-level lookup.

### Constant-expression GNU assembly

GCC 15 permits inline-assembly strings generated by constexpr evaluation
(gcc-15.1). Clang 21 also permits GNU `asm` strings as constant expressions
(clang-21.1):

```cpp
asm((std::string_view("nop")) ::: (std::string_view("memory")));
```

Clang 21 additionally implements P2719R5 type-aware allocation and deallocation
as an extension in every C++ language mode.

## C++26 language facilities

### Clang facilities (clang-20.1)

Clang implements variadic friends (P2893R3), constexpr placement new
(P2747R2), and the Oxford variadic comma (P3176R1). User-defined
`static_assert` messages are accepted as an extension back to C++11.
Implementation builtins include `__builtin_is_virtual_base_of` and
`__builtin_is_within_lifetime`.

### GCC syntax and compatibility (gcc-15.1)

GCC implements pack indexing, attributes on structured bindings, reason strings
in `= delete("reason")`, and structured bindings as conditions. The basic
character set includes `@`, `$`, and backtick.

Compatibility rules also tighten: standard attributes are ignorable where
required, module declarations cannot be macros, deleting a pointer to an
incomplete type is ill-formed, deprecated array comparisons are removed, and
the notion of trivial types is deprecated.

### Clang structured bindings and relocation (clang-21.1)

Clang implements structured-binding packs, structured-binding declarations as
conditions, attaching `main` to the global module, and the initial
trivial-relocation facility. `__builtin_structured_binding_size(T)` reports the
number of bindings produced by destructuring `T`.

For relocation, use `__builtin_is_cpp_trivially_relocatable` and
`__builtin_trivially_relocate`; `__is_trivially_relocatable` is deprecated.
Relocatable but non-trivially-copyable objects must not simply be copied with
`memcpy`.

### Trivial-relocation rollback (clang-22.1)

After P2786 left C++26, `__builtin_is_replaceable`,
`trivially_relocable_if_eligible`, and `replaceable_if_eligible` were removed.
`__builtin_is_cpp_trivially_relocatable` and
`__builtin_trivially_relocate` remain with P2786-style semantics, but a type
can no longer be explicitly marked relocatable.

### GCC reflection and core language (gcc-16.1)

P2996R13 reflection requires both `-std=c++26` and `-freflection`:

```sh
g++ -std=c++26 -freflection source.cc
```

Support includes reflection annotations, parameter reflection, base-class
subobject splicing, reflection error handling, and `define_static_string`,
`define_static_object`, and `define_static_array`.

GCC also implements expansion statements, contracts, erroneous behavior for
uninitialized reads, constexpr exceptions, constexpr virtual inheritance,
partial program correctness, and defined preprocessing behavior.

## C++20 modules

### Reduced BMIs in Clang

`-fmodules-reduced-bmi` became the non-experimental spelling in clang-20.1.
Clang enables Reduced BMI mode by default in clang-22.1. Two-phase module
compilation must support reduced BMIs, and code must not depend on
implementation details that the reduced form discards.

### GCC standard modules (gcc-16.1)

With experimental module support enabled, `--compile-std-module` builds the
`<bits/stdc++.h>` header unit and the `std` and `std.compat` modules before
explicit input files. Once that header unit exists, eligible standard-header
includes can be translated into imports.

Keep BMIs and header units isolated by compiler version, standard library,
target, language mode, and relevant build flags.

## Type traits and overload selection

On targets with 128-bit integer support, strict dialects now make traits such as
`std::is_integral<__int128>` true, matching GNU dialects. This can change
constraints and overload selection (gcc-16.1).

## Standards status and known limits

The `standards-status` inventory classifies C++20, C++23, C++2c, and C++2d
support as partial.

### C++20

Coroutines are fully supported except on Windows, where stability and ABI
issues remain. On 32-bit x86 Windows, `__cpp_impl_coroutine` is not defined and
using coroutines warns.

For modules, P1857R3 is not implemented until Clang 23 and P1815R2 remains
partial. Generalized scalar non-type template parameters do not fully support
references to instantiation-dependent objects or subobjects. Alias-template
CTAD is implemented, but `__cpp_deduction_guides` has not been updated to
advertise it.

### C++23

In `-std=c++23`, the status table still marks constexpr
`<cmath>`/`<cstdlib>`, standard extended floating-point types, CTAD from
inherited constructors, and explicit lifetime management as unsupported.
Unicode identifiers are supported without NFC normalization checking.

### C++26

Use `-std=c++2c` with Clang. Clang 23 enforces that module declarations cannot
be macros and only partially implements expansion statements because iterating
expansions are diagnosed. Clang 24 adds constexpr virtual inheritance.
Contracts, reflection, `#embed`, constexpr exceptions, trivial unions, and
several other adopted facilities remain unsupported there.

### C++29

Clang accepts `-std=c++2d`, but support is very preliminary and most listed
proposals are unsupported. More named universal character escapes arrive in
Clang 23; the mode is not evidence of broad C++29 conformance.
