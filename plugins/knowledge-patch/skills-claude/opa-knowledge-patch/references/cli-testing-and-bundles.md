# CLI, Testing, and Bundles

## Format, parse, evaluate, and debug

- In v1 mode, `opa fmt` preserves `rego.v1` and `future.keywords` imports so
  modules retain compatibility intent for older consumers (since 1.0.0).
- The debugger accepts YAML input (since 1.0.0).
- Formatting no longer mutates string contents or panics on unexpected
  comments (since 1.4.0). Reformat with a corrected release before trusting
  diffs made by an affected formatter.
- `opa parse --v0-compatible policy.rego` parses legacy modules in their
  intended compatibility mode (since 1.6.0).
- `opa eval` writes evaluation errors to stderr (since 1.9.0). Automation must
  collect the error stream separately from stdout.
- `opa fmt` does not overwrite a file when formatting produces no changes
  (since 1.13.0), preserving its modification time.
- OPA 1.18.0 incorrectly expanded single-item arrays, objects, and sets over
  multiple lines. Use 1.18.2, which again lets existing source newlines decide
  one-line versus multiline formatting. The formatter also preserves `with`
  clauses after comments in object values and lone `with` placement on
  closing-bracket lines.

## Parameterized and parallel tests

Data-driven tests can emit hierarchical named cases by putting the case name
in the rule head (since 1.2.0):

```rego
package example_test

test_concat[note] if {
	some note, tc in {
		"empty": {"a": [], "b": [], "want": []},
		"filled": {"a": [1], "b": [2], "want": [1, 2]},
	}
	array.concat(tc.a, tc.b) == tc.want
}
```

`opa test` reports every generated case beneath the test rule. Since 1.3.0,
the report counter includes parameterized cases; in non-verbose mode its
summary includes only failed sub-test cases.

Tests run in parallel by default, one execution thread per available CPU core
(since 1.6.0). Force sequential execution where ordering matters:

```sh
opa test . --parallel=1
```

JSON results can sort by duration (since 1.13.0). Test results stream one case
at a time (since 1.17.0), and failures under `--coverage` include full errors,
so output consumers must handle incremental records.

Coverage reports include source ranges and track inline rule heads and
conjunction expressions (since 1.18.0). Rebaseline stored coverage locations
and totals after upgrading.

## Bundle construction and checking

Optimized builds reject single-term entrypoint paths (since 1.3.0). Specify at
least package and rule:

```sh
opa build -O=1 -e=authz/allow .
```

The bundle API assigns a default Rego version when the caller omits one (since
1.5.0). Embedded producers must account for resulting version metadata instead
of assuming the field remains unset.

`opa check --bundle` detects conflicts where JSON or YAML base documents
overlap virtual documents generated by policy rules (since 1.6.0):

```sh
opa check --bundle ./bundle
```

Bundle polling intervals are validated (since 1.12.0), preventing a malformed
configuration from causing nanosecond-level polling.

Per-module Rego-version lookup is corrected and overlapping
`file_rego_versions` patterns resolve deterministically (since 1.18.0).
Recheck mixed-version bundles whose manifests contain overlapping patterns.

## Wasm bundles and results

`opa build` can preserve `print` statements when targeting `wasm` (since
1.0.0). Enable that option when runtime diagnostics must survive compilation.

Wasm and non-Wasm evaluation now agree for reference-head rules affected by an
over-eager planner optimization (since 1.3.0). Re-test affected policies
because corrected Wasm results can differ.

## Capability artifacts

OPA 1.4.1 updated its Go runtime to 1.24.2 for CVE-2025-22870 and
CVE-2025-22871 but omitted `capabilities/v1.4.1.json`. Use 1.4.2 for the
complete patched 1.4 release when tooling consumes versioned capability files.
